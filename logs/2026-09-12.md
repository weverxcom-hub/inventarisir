## Lanjutan sesi — Perbaikan 3 temuan kritis (K-01, K-02, K-03)

User minta perbaiki langsung dengan teliti. Perubahan:

- **K-01** — [src/app/api/inventory/route.ts](src/app/api/inventory/route.ts): tambah `await requireAuth();` di awal `GET`, dan perbaiki catch block-nya supaya mengembalikan 401 (bukan selalu 500) saat belum login — konsisten dengan pola di rute Procurement.
- **K-02** — [src/app/auth/callback/route.ts](src/app/auth/callback/route.ts): setelah tukar kode SSO, email pengguna sekarang dicocokkan ke sheet **Users** milik aplikasi; role token sesi diambil dari sheet itu (bukan lagi dari klaim `role` mentah yang dikirim server SSO). Kalau email belum terdaftar di sheet Users → redirect ke `/login?error=sso_unregistered` (akses ditolak, bukan auto-provisioned). Juga sekaligus membenahi K-03: deteksi `isSecure` sekarang mengecek `req.nextUrl.protocol === "https:"` dulu (baru fallback ke `NEXTAUTH_URL`), jadi tetap benar walau env var production kelupaan/salah diisi.
- Ikutan dari K-02: [src/app/login/page.tsx](src/app/login/page.tsx) sekarang membaca query param `?error=` dan menampilkan pesan yang sesuai (`sso_failed` / `sso_unregistered`) — sebelumnya redirect ini ada tapi pesannya tidak pernah ditampilkan ke user. Perlu dibungkus `<Suspense>` karena pakai `useSearchParams()` (kalau tidak, `next build` akan gagal/warning saat prerender static page).

### Verifikasi
- `npx tsc --noEmit` → bersih.
- `npm run build` → sukses, `/login` tetap ter-prerender statis (○), tidak ada error dari perubahan Suspense.
- Uji live via browser (dev server): `GET /api/inventory` tanpa login sekarang mengembalikan `{"error":"Unauthorized"}` (sebelumnya membocorkan seluruh daftar inventaris). Halaman `/login?error=sso_unregistered` menampilkan pesan "Akun Anda belum terdaftar..." dengan benar, tanpa error console.

## Lanjutan sesi — Perbaikan semua 10 temuan "penting" (P-01 s.d. P-10)

User minta "perbaiki semuanya". Dikerjakan satu per satu:

- **P-01**: validasi input server ditambahkan di `POST/PUT /api/inventory` dan `POST /api/procurement` (field wajib, quantity harus integer positif, harga non-negatif, condition harus enum valid) — pola yang sudah ada di rute Users, sekarang konsisten di semua rute.
- **P-02**: [src/lib/rate-limit.ts](src/lib/rate-limit.ts) (baru) — limiter in-memory per-proses, kunci setelah 5 gagal login dalam 15 menit per email, dipasang di `src/lib/auth.ts`. **Dibuktikan langsung**: attempt ke-6/7 turun dari ~450-1500ms jadi ~18-29ms (skip total ke Sheet+bcrypt).
- **P-03**: [src/lib/google.ts](src/lib/google.ts) — `uploadFileToDrive` tidak lagi memberi izin publik "anyone". File nota kini hanya bisa diakses lewat proxy baru **[src/app/api/drive-file/[id]/route.ts](src/app/api/drive-file/%5Bid%5D/route.ts)** yang mewajibkan login (`requireAuth()`). Link "Lihat Nota" di halaman Pengadaan & Persetujuan diarahkan ke proxy ini.
- **P-04**: kolom `Updated_By`/`Updated_At` ditambahkan ke sheet Procurement (README diperbarui), diisi otomatis di approve/reject/complete, ditampilkan di tabel Riwayat halaman Persetujuan. Inventory CRUD audit trail sengaja belum digarap (scope decision, masuk roadmap).
- **P-05**: `npm audit fix` dijalankan — menambal qs/uuid/next-auth/postcss-selector-parser tanpa breaking change. Sisa kerentanan (bundel Next.js) butuh v16 major, sesuai rencana ditunda.
- **P-06**: README.md — instruksi generate hash bcrypt diganti dari bcrypt-generator.com (situs pihak ketiga) ke perintah `node -e` lokal.
- **P-07**: catatan "perubahan role baru berlaku setelah re-login" sekarang tampil langsung di halaman Kelola Pengguna, bukan cuma di README.
- **P-08**: race condition ID generator diperbaiki — `generateItemId`/`generateRequestId` diganti jadi `createInventoryRow`/`createProcurementRow` di [src/lib/google.ts](src/lib/google.ts) yang membungkus **seluruh** baca-max-lalu-tulis dalam satu antrean async per proses (bukan cuma hitung ID-nya), lalu semua caller (`inventory/route.ts`, `procurement/route.ts`) diupdate.
